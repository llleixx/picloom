# 数据、升级与备份

## 哪些数据需要保留

| 数据                              | 作用                                         |
| --------------------------------- | -------------------------------------------- |
| SQLite 数据库或 PostgreSQL 数据库 | 文件记录、用户、任务和插件实例配置           |
| `ENCRYPTION_KEY`                  | 解密插件凭证；恢复必须保留原值               |
| `DATA_DIR/plugins`                | 外部插件包                                   |
| `DATA_DIR/delivery-settings.json` | Web 保存的运行设置                           |
| 本地存储根目录、远端存储对象      | 实际图片内容                                 |
| 临时目录                          | 可能仍被未完成任务使用，不应在运行中手动清空 |

派生缓存可重建。仅复制图片目录不能恢复账户、公开路径和副本关系。

## 内置备份

当前内置备份只支持 SQLite，由 Owner 操作。默认保存在应用数据目录旁的 `backups/`；Docker 部署时对应宿主机 `data/backups/`。

### 创建与下载

1. 打开 **系统** 页面，在备份区域点击创建备份。
2. 等待操作完成，确认列表中出现新备份及其时间、大小。
3. 下载到服务器之外的位置，并另行保管部署所用的 `ENCRYPTION_KEY`。

### 恢复

1. 确认目标部署使用对应的加密密钥，并保留当前数据的备份。
2. 在系统页面上传已有备份；已在列表中的备份可直接选择恢复。
3. 核对恢复提示并确认，等待恢复完成后重新登录。
4. 检查存储源状态，并打开几张本地和远端图片确认可用。

上传备份仅把文件加入备份列表，点击恢复才会替换数据。

备份会进入维护状态：停止接收普通请求、暂停新任务领取、等待在途工作结束后关闭应用并制作快照。慢任务或不响应取消的插件可能延长等待。

内置备份包含数据库、设置、插件及可识别的本地存储目录等数据，**不打包 S3 等远端对象**。下载的备份包含敏感配置，应作为私有文件保存。

恢复会替换当前部署的数据，应在确认目标环境后操作。加密密钥必须匹配；恢复不会替你找回丢失的远端图片。

## PostgreSQL

使用数据库工具备份 PostgreSQL，同时保存 Picloom 数据目录与备份目录、密钥及本地存储目录。需要一致恢复点时，先停止 Picloom，再协调数据库与文件备份。

## 升级

先备份，再更新镜像并重建容器，保留原数据目录和原密钥：

```sh
docker compose -f compose.yml pull
docker compose -f compose.yml up -d
```

自行构建镜像时，用重新构建代替 `pull`。

当前仍处于 `0.1.0` 开发阶段，数据库初始化结构有校验，不承诺任意开发提交之间都可直接升级。若出现结构校验不匹配，不要手改校验值绕过；先核对目标版本的数据兼容说明并保留备份。
