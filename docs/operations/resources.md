# 容量与并发

## 两个独立空间上限

| 设置                       | 覆盖内容                                               | 达到上限时                                             |
| -------------------------- | ------------------------------------------------------ | ------------------------------------------------------ |
| 临时缓存 `uploadTempBytes` | 上传暂存、分片、处理中间文件、仍被后台任务使用的源文件 | 新的预留或写入被拒绝，等待已有工作释放空间             |
| 派生缓存 `cacheBytes`      | 访问派生结果和缩略图内容                               | 尝试淘汰旧缓存；仍不足则跳过缓存写入，正常返回处理结果 |

设置入口：**设置 → 缓存**，分别调整“临时缓存上限”和“派生缓存上限”。两项独立设置，默认均为 1 GiB。

这两个值不是磁盘总配额，也不限制全部内存。原图、数据库、日志、备份和插件包不属于派生缓存配额；元数据和文件系统开销也需要额外空间。

临时文件只有在不再使用且删除成功后才释放对应记账。缓存过期会清理；插件安装暂存票据有效期为 15 分钟，维护循环每小时清理一次过期包，安装完成后会移出暂存位置。

## 并发设置

- 上传并发：同时接收的上传工作。
- 分片并发：上传会话内同时处理的分片。
- 图片处理并发与队列：控制图片处理资源使用和等待长度。
- 后台任务并发：冗余写入、保存后处理和删除任务的执行名额。

这些设置作用不同，不要同时大幅提高。图片解码、插件缓冲和存储 SDK 都可能占用额外内存。

后台任务完成后会补充空闲名额；定时轮询发现新任务与到期重试。异常恢复单独运行，同一文件的恢复和任务执行互相避让。

## 服务端缓存与客户端缓存

以上设置均位于 **设置 → 缓存**。服务器派生缓存由容量和 TTL 控制；浏览器/CDN 缓存通过响应头控制客户端行为，不占用服务器缓存配额，默认有效期为 300 秒（5 分钟），设为 0 则每次使用缓存前重新验证。清空服务器缓存不会让浏览器已经缓存的图片立即失效。

参数默认值和单位见 [设置参考](../reference/settings.md)。
