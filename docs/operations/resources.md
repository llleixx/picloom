# 容量与并发

## 查看统计

管理员打开 **系统 → 统计概览**，选择最近 7、30 或 90 天，查看新增图片数和大小趋势；切换数量与大小，点击日期后选择「查看图片」进入明细。图片格式通过环形图与数值、占比列表展示，存储实例通过横向条形图比较账面大小；点击格式名称或存储实例可进入筛选结果，「按大小查看图片」将已知大小较大的图片排在前面。

图片总数、原图大小和格式分布仅统计已就绪图片，每张只计一次；新增趋势按浏览器本地日期汇总这些图片的创建时间，区分上传和导入。

存储分布按所有未删除副本记账，包含待写入和失败副本，不代表远端实际占用；配置了容量上限的实例会同时显示上限。本地目录大小来自实际扫描，数据磁盘可用空间仅指数据目录所在文件系统。

「异常图片」汇总已屏蔽、整图删除失败，以及副本写入、保存后处理或删除已停止重试且仍未处理的图片，每张计一次，点击进入筛选列表。上传失败后的自动清理不计入，清理最终失败才计入；已删除副本关联的失败历史不计入。运行时间、本地磁盘容量和缓存明细、完整失败任务列表、缓存清理和备份恢复位于 **系统 → 运行维护** 页签。

## 文件限制、磁盘空间与内存

| 类型 | 控制什么 | 设置入口 |
| --- | --- | --- |
| 文件与图片限制 | 单文件大小、图片边长和像素数 | 设置 → 上传、处理与任务 |
| 缓存容量 | 临时缓存与派生缓存各自可用的空间 | 设置 → 缓存 |
| 并发与队列 | 同时执行和等待的工作数量 | 设置 → 上传、处理与任务 |

缓存上限不是磁盘总配额，原图、数据库、备份和插件包仍需额外空间。文件大小也不等于处理时的内存占用：图片解码、处理中间结果和插件缓冲都可能占用内存。

## 临时缓存与派生缓存

两项独立设置，位于 **设置 → 缓存**：

| 缓存 | 用途 | 默认上限 | 达到上限时 |
| --- | --- | --- | --- |
| 临时缓存 | 上传暂存、分片、处理中间文件及后台任务仍需使用的源文件 | 1 GiB | 拒绝新的空间预留或写入，等待已有工作释放空间 |
| 派生缓存 | 访问处理结果和缩略图 | 1 GiB | 尝试淘汰旧缓存；空间仍不足时跳过缓存写入，返回本次处理结果 |

临时缓存会为分片合并等后续工作预留空间，因此实际文件尚未占满上限时，也可能无法接收新上传。文件不再使用且删除成功后才释放对应空间，不要在运行中手动清空临时目录。

派生缓存默认保留 24 小时。缓存被淘汰、过期或未能写入后，再次访问可能需要重新处理；增加容量只能减少这类重复处理，不能提高首次处理的速度。

## 并发与队列

| 设置 | 作用 | 默认值 | 设置入口 |
| --- | --- | --- | --- |
| 并发上传文件数 | 限制同时接收或完成的上传工作，也用于浏览器安排文件上传 | 4 | 上传 |
| 单文件并发分片数 | 限制一个上传会话同时接收的分片 | 2 | 上传 |
| 图片处理并发数 | 限制同时执行的受控图片处理工作 | 2 | 处理与任务 → 高级设置 |
| 图片处理队列长度 | 处理名额用尽后允许等待的工作数量 | 16 | 处理与任务 → 高级设置 |
| 存储写入并发数 | 限制同时执行的上传写入、剩余副本写入和写入重试 | 4 | 处理与任务 → 高级设置 |
| 上传后处理并发数 | 限制同时执行的完整保存后流水线 | 2 | 处理与任务 → 高级设置 |
| 删除并发数 | 限制同时执行的远端副本删除 | 2 | 处理与任务 → 高级设置 |

图片处理队列满时，新请求返回忙碌（`BUSY`）。增加队列只增加等待名额，不会让处理更快。

写入、上传后处理和删除独立使用名额，不互相借用，默认最多同时运行 8 个任务。提高并发后补充派发；降低并发不打断正在运行的任务。写入优先推进尚无成功副本的上传，持续上传时剩余副本可能等待更久，并继续占用临时内容。

这些值分别控制不同环节，不是一个全局并发上限。存储插件还可能有自己的分片并发设置；同时提高多个值可能叠加内存、磁盘和网络压力。

## 什么时候调整

先使用默认值，根据实际现象调整，每次只改一类参数并观察效果。

| 现象 | 调整方向 |
| --- | --- |
| 图片处理时内存吃紧 | 检查图片像素数和同时处理数量，必要时降低图片处理并发 |
| 上传提示临时缓存不足 | 先检查未完成上传和后台任务；确认磁盘有余量后，再考虑增加临时缓存上限 |
| 后台任务积压，机器资源有余量 | 先检查存储端错误或限流；没有这些问题时，可适当提高积压队列的并发 |
| 热门缩略图反复处理 | 检查派生缓存容量和保留时间，避免结果频繁淘汰或过期 |
| 上传速度慢 | 先区分客户端带宽、服务器网络和存储端瓶颈，再调整上传或分片并发 |

提高并发不保证提速。存储端已经限流、CPU 已满或内存不足时，增加工作数量可能使等待更长。

## 服务端缓存与客户端缓存

这两类缓存都在 **设置 → 缓存** 中配置，但作用不同：

| 类型 | 存在哪里 | 控制项 | 清理或失效的影响 |
| --- | --- | --- | --- |
| 派生缓存 | Picloom 服务器 | 容量上限、保留时间 | 后续访问可能重新处理，不会清除客户端已有缓存 |
| 浏览器/CDN 缓存 | 浏览器或 CDN | 图片响应缓存时间 | 通过响应头控制客户端行为，不占服务器缓存配额 |

浏览器/CDN 缓存默认有效期为 300 秒（5 分钟）；设为 0 表示缓存使用前需要重新验证，不等于禁止保存缓存。有效期内，即使站内删除或屏蔽图片，客户端已有缓存也可能继续展示。

完整参数和单位见 [设置参考](../reference/settings.md)，CDN 配置见 [域名与反向代理](./proxy.md#cdn-与防盗链-可选)。
