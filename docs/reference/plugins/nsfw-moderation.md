# 本地 NSFW 审核

使用随插件提供的 NSFWJS MobileNetV2 模型，在服务器 CPU 上审核色情、色情动漫及可选的性感内容。无需 GPU、外部服务或凭据，运行时不下载模型、不上传图片。

`picloom.nsfw-moderation` · `processor` · `post_save`

## 开始使用

1. 按[安装插件](../../guide/plugins.md)安装 ZIP，在 **配置 → 流水线** 的保存后阶段添加 **本地 NSFW 审核**。
2. 选择检测类别、阈值和命中处置，保存后将流水线关联到上传配置。
3. 上传测试图片，在图片详情查看审核结果。需要通知时，将通知插件放在审核步骤之后。

## 配置

| 配置 | 默认值 | 范围 |
| --- | --- | --- |
| 检测类别 `categories` | `Porn`、`Hentai` | 色情、色情动漫；可选性感内容 `Sexy`，至少一项 |
| 命中阈值 `threshold` | `0.8` | 大于 0、至多 1，所有选定类别共用 |
| 命中处置 `blockAction` | `block` | 屏蔽 `block` 或删除 `delete` |
| 最大抽帧数 `maxFrames` | `5` | 1–10；1 表示只审首帧 |
| 文件读取上限 `maxContentMiB` | `20` | 高级设置，1–100 MiB |
| 执行超时 `timeoutMs` | `30000` | 高级设置，1000–120000 毫秒 |

任一抽样帧的任一选定类别达到阈值即命中，不累加不同类别分数。阈值不代表准确率，应结合误判和漏检调整；启用 `Sexy` 后，泳装、写真等也可能命中。

## 图片与结果

静态图审核一帧；GIF、动态 WebP 等多帧图片按帧序号均匀抽样，包含首尾帧，不足上限时全部审核。例如 21 帧取 5 帧时，审核第 1、6、11、16、21 帧。未抽中的画面不在审核范围内；增加抽帧数会增加 CPU 消耗和耗时。

格式支持取决于服务器的解码能力，单帧最多 4000 万像素。透明区域按白色背景识别，SVG 仅审核静态画面，原图不变。超时覆盖模型加载、读取、解码和推理，不含排队等待。

审核摘要记录模型、类别、阈值、各类别最高分、命中类别、总帧数和实际审核帧数。最高分可能来自不同帧。

## 生效边界

审核完成前图片可能已可访问。通过结果不会撤销前序步骤的屏蔽或删除决定；修改配置不会自动重审已完成的图片。

超限、不支持的格式、解码或模型加载失败、无效输出和超时会记录任务错误，不算审核通过，也不会自动屏蔽图片或重试。其他错误沿用任务重试规则；修复原因后可在后台任务中重试。
