# 插件基础

首次开发可先按[插件快速开始](./plugin-tooling.md)创建项目。

## 插件类型

| 类型                 | 职责                         | 使用位置 |
| -------------------- | -------------------------------- | ---------- |
| 路径插件 `path`      | 返回公开路径中的相对部分和存储键 | 上传配置   |
| 存储插件 `storage`   | 实际写入、读取、删除文件         | 存储源     |
| 处理插件 `processor` | 转换图片或执行保存后操作 | 流水线步骤 |

处理插件包含上传 `upload`、访问 `access`、保存后 `post_save` 三个阶段。一个插件可以支持多个阶段，但每个阶段分别定义配置和实现。接口见[处理插件](./plugin-api.md)。

## 源码与安装包

最小源码目录和构建后的安装包如下：

```text
my-plugin/                    插件 ZIP 根目录
├── plugin.json   ──────────→  ├── plugin.json
└── src/index.ts  ── 构建 ──→  └── index.js
```

| 文件           | 职责                                               |
| -------------- | -------------------------------------------------- |
| `plugin.json`  | 清单，告诉 Picloom 包的身份、版本、类型和入口位置  |
| `src/index.ts` | 插件源码，默认导出一个插件定义，描述配置及实现方法 |
| `index.js`     | 构建后的 JavaScript 入口，Picloom 实际加载它       |

源码可以拆成多个文件，也可以引用依赖。示例构建会把需要的代码合并进入口；若保留其他运行文件，它们也必须包含在包中。Picloom 不会自动安装包内的 npm 依赖。

独立项目通过 `@picloom/plugin-sdk` 引用 SDK，提供类型和辅助函数，例如：

```ts
import { PluginError, type Definition } from "@picloom/plugin-sdk";
```

独立模板从清单读取身份字段，配置和实现留在源码中。依赖打包规则见
[构建依赖](./plugin-release.md#构建依赖)，宿主能力见[宿主服务](./plugin-services.md)。

## 清单 plugin.json

<<< ../../examples/path/plugin.json

| 字段         | 类型                                 | 必填 | 含义与约束                                                                                                    |
| ------------ | ------------------------------------ | ---- | ------------------------------------------------------------------------------------------------------------- |
| `id`         | `string`                             | 是   | 稳定标识；小写字母开头，仅含小写字母、数字、点、下划线、短横线，最长 100 字符；外部插件不能以 `builtin.` 开头 |
| `version`    | `string`                             | 是   | 代码版本；数字开头，仅含字母、数字、`.`、`+`、`-`，最长 64 字符，例如 `1.0.0`                                 |
| `kind`       | `"path" \| "storage" \| "processor"` | 是   | 插件类型                                                                                                      |
| `apiVersion` | `1`                                  | 是   | 当前支持的宿主接口版本                                                                                        |
| `entry`      | `string`                             | 是   | 以 `.js` 结尾的包内相对路径，例如 `index.js`                                                     |
| `author`     | `string`                             | 否   | 插件列表与详情显示的作者，最多 200 字符，去除首尾空白后须非空 |

入口定义的 `id`、`version`、`kind` 和 `apiVersion` 必须与清单一致。

## 入口定义

入口默认导出 `Definition` 对象。下表适用于所有插件类型。

| 字段                                  | 类型                                     | 必填 | 用途                                                                                                                          |
| ------------------------------------- | ---------------------------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------- |
| `id`、`version`、`kind`、`apiVersion` | 同清单                                   | 是   | 与安装包对应                                                                                                                  |
| `defaultLocale`                       | `string`                                 | 是   | 内容默认语言，使用规范语言代码，例如 `en-US`                                                                                  |
| `nameKey`                             | `string`                                 | 是   | 插件名称翻译键                                                                                                                |
| `descriptionKey`                      | `string`                                 | 否   | 插件说明翻译键                                                                                                                |
| `messages`                            | `Record<string, Record<string, string>>` | 是   | 按语言保存名称、说明及所有阶段字段文案；默认语言必须包含 `nameKey` 引用的非空名称，见[包文案与表单提示](./package-localization.md) |

路径和存储定义在顶层声明下表中的配置描述。处理插件在 [`stages`](./plugin-api.md#定义与阶段) 中逐阶段声明。存储定义还支持可选的 [`localDirectory`](./plugin-storage.md#本地目录声明-可选)。

每份配置通过 `createInstance` 创建运行对象。实例复用及释放规则见[并发调用与实例生命周期](./plugin-errors.md#并发调用与实例生命周期)。

插件运行在服务主进程，没有沙箱。安装需要 Owner 权限，只安装可信代码。

## 配置描述字段

`Descriptor<R>` 的泛型参数 `R` 表示运行对象类型。

| 字段 / 方法           | 类型                                     | 必需 | 作用                                                             |
| --------------------- | ---------------------------------------- | ---- | ---------------------------------------------------------------- |
| `configSchemaVersion` | 正整数                                   | 是   | 配置结构版本，从 `1` 开始                                        |
| `configSchema`        | `ConfigSchema`                           | 否   | 根类型为对象的配置 Schema；省略表示没有自定义配置项，只接受 `{}` |
| `createInstance`      | 异步函数                                 | 是   | 根据配置创建运行对象                                             |
| `validateConfig`      | 异步函数                                 | 否   | 补充配置语义校验                                                 |
| `migrateConfig`       | 异步函数                                 | 否   | [升级时转换旧配置](./plugin-release.md#migrateconfig-转换旧配置) |

上传和访问阶段还可声明 [`paramsSchema`](./plugin-config.md#固定配置与请求参数)。
