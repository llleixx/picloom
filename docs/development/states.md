# 状态与后台任务

文件、存储副本和后台任务分别表达不同事实，不应只用一个“成功／失败”字段代替。

## 文件状态

| 状态        | 含义                         |
| ----------- | ---------------------------- |
| `preparing` | 上传尚未发布                 |
| `ready`     | 可正常提供访问               |
| `blocked`   | 已屏蔽，保留内容供管理       |
| `failed`    | 上传失败，等待清理           |
| `deleting`  | 已停止正常公开访问，正在清理 |
| `deleted`   | 删除流程已完成               |

文件 `ready` 不表示所有冗余或保存后任务都已完成。

## 副本状态

| 阶段     | 状态                                      |
| -------- | ----------------------------------------- |
| 写入     | `pending` → `writing` → `ready`           |
| 写入异常 | `write_failed` 或 `write_unknown`         |
| 删除     | `delete_pending` → `deleting` → `deleted` |
| 删除异常 | `delete_failed` 或 `delete_unknown`       |

`unknown` 表示远端结果尚不确定，需要恢复或后续删除确认。已取消且未写入的副本归入 `deleted`，没有单独的副本 `cancelled` 状态。

## 任务状态与领取

任务类型为 `write`、`action`、`delete`；状态为 `pending`、`running`、`success`、`failed`、`cancelled`。

候选查询先校验文件状态，再限制领取数量：写入允许 `ready/blocked`，保存后处理只允许 `ready`，删除允许 `ready/blocked/deleting`。执行事务再复查一次，避免查询后状态改变。

重试受 `retryable`、尝试次数与退避时间约束。失败的删除任务可人工重试；不要把其他失败都当作可重放操作。

## 临时文件何时回收

仍有待执行或正在执行的写入、保存后任务时，需要保留源文件。没有这些需求后，还要等相关在途使用结束，删除成功才释放空间记账。

即使远端写入结果仍为未知，也不必无限保留已经没有本地任务需求的源文件。远端副本状态与本地临时空间生命周期是两件事。
