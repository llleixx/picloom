# 存储源与存储组

存储源负责连接实际存储；存储组决定一次上传使用哪些存储源。即使只使用本地磁盘，也需要创建一个包含该源的存储组，再交给上传配置使用。

## 添加本地存储

在 **配置 → 存储源** 点击创建，选择 **本地存储**，填写名称和根目录后保存。

根目录可填写 `./images`，相对于应用数据目录解析，保存时转换为绝对路径。使用仓库提供的 Docker Compose 时，对应宿主机 `./data/app/images`，重建容器后仍会保留。也可以填写服务进程可读写的绝对路径。

根目录是服务器或容器内的路径。若要使用宿主机上的其他磁盘，需要先将目录挂载到容器，再填写挂载后的容器路径。

## 添加 S3 兼容存储

先在存储服务中创建桶并取得访问凭证，然后在 **配置 → 存储源** 选择 **S3 兼容存储**。

| 字段 | 填写说明 |
| --- | --- |
| 端点 | 服务商提供的 S3 API 地址，包含 `https://`；不是桶的公开访问域名。AWS S3 可留空，由 SDK 根据区域选择 |
| 区域 | 必填，按存储服务商要求填写，无默认值 |
| 存储桶 | 已创建的桶名称，不含 URL 或目录 |
| 访问密钥 ID、访问密钥 | 对应服务的凭证；读写、删除和导入所需权限应覆盖相应操作 |
| 路径寻址 | 默认开启。按服务商对 path-style / virtual-hosted-style 的要求设置 |
| 对象前缀 | 可选，例如 `picloom`；不带开头或结尾的 `/`。公开链接不会因此多出这一段 |
| 会话令牌 | 使用临时凭证时填写，普通长期凭证可留空 |
| 读取方式 | 默认应用转发；也可选择签名重定向或公开地址重定向，填写对应配置。详见 [S3 配置说明](../reference/plugins/s3.md) |

分片阈值、分片大小和并发数可先保留默认值。它们控制 Picloom 向 S3 写入，与浏览器向 Picloom 分片上传是两个环节。

选择签名重定向时仍应分享 Picloom 链接；浏览器跳转后的签名链接会过期。图片需要缩放或添加水印时，Picloom 仍需读取存储内容。

## 创建存储组

1. 确认要加入的存储源显示「就绪」。
2. 在 **配置 → 存储组** 点击创建，添加存储源，选择策略与副本数后保存。
3. 在 **配置 → 上传配置** 选择该组。上传一张测试图片并打开返回链接，再到图片详情确认副本状态。

两种常用配置如下：

| 用途 | 成员 | 存储选择策略 | 副本数 |
| --- | --- | --- | --- |
| 只存本地 | 本地图片 | 按优先级 | `1` |
| 本地与 S3 各存一份 | 本地图片在前，S3 在后 | 按优先级 | `2` |

按优先级时，成员顺序决定选择顺序；加权随机时，权重决定被选中的相对概率。上传目标选择与读取失败回退共用此策略，每次不重复选择同一存储源。读取仅从已有的可用副本中选择；图片处理和缩略图的原图下载中断时会尝试其他副本。

副本数表示总份数：`1` 保存一份，`2` 保存两份。每次上传选择对应数量的不同存储源；可用源不足时无法上传。

首份副本保存后即可返回链接，其余副本继续写入。

## 调整或更换存储

修改存储组只影响后续上传，已有图片不会自动搬迁或补齐副本。已有副本仍依赖原存储源的配置，删除源前需要处理其配置引用与副本。

本地根目录、S3 桶等定位字段不可直接修改。要更换存储位置，应创建新存储源，再调整存储组。已有远端图片可通过 [导入](./files.md#导入已有图片) 登记；导入不会复制图片。

其他存储插件见 [内置插件](../reference/plugins.md)。

## 存储容量

在 **配置 → 存储源** 编辑容量上限，留空表示不限。上限约束新副本，已登记的副本仍可继续写入或重试。列表容量按副本记账，可能与存储服务显示的实际用量不同。

## 清理与删除存储源

1. 打开存储源的 **… → 清理**，按面板提示将它从存储组中移除。
2. 选择删除文件或仅解除引用。要保留没有其他可用副本的图片，请勾选对应选项。见[删除图片](./files.md#删除图片)。
3. 点击「开始清理」。有失败项时，修复问题后点击「重试失败项」。
4. 引用数归零后，确认删除存储源配置。

清理只处理提交时已登记的副本。仅解除引用时，文件会留在存储中。
