# 上传配置与公开路径

上传配置将存储、文件路径和处理步骤组合成一个上传入口。上传者选择配置即可，不需要每次选择存储桶或水印规则。

例如，“博客图片”使用 `/blog/` 前缀并添加水印，“截图”使用 `/screenshots/` 前缀且不做上传处理；两者可以共用同一个存储组。

## 创建上传配置

先准备好 [存储组](./storage.md)，再打开 **配置 → 上传配置**，点击创建。

| 配置项 | 示例与作用 |
| --- | --- |
| 名称 | `博客图片`，显示在上传页的选择列表中 |
| 公开前缀 | `/blog/`，作为公开图片路径的开头；不要使用 `/api/`、`/app/` 等系统路径 |
| 路径插件 | 默认选择“随机路径”，生成 32 位随机文件名；目录层数保留 `2` |
| 存储组 | 选择已建立的存储组，决定主副本和冗余副本的位置 |
| 允许格式、文件大小 | 限制这个入口接收的图片；其他全局及用户限制仍然生效 |
| 上传流水线 | 可选，保存前进行缩放、水印等处理 |
| 保存后流水线 | 可选，保存后在后台审核或发送通知 |
| 允许游客上传 | 需要匿名上传时才开启，还需配置游客额度 |

保存后回到上传页，确认该配置可以选择，并上传一张图片。若不可用，查看配置提示，检查路径插件是否就绪、存储组是否有足够的可用成员。

## 链接如何形成

公开链接由图片域名、公开前缀和路径插件生成的路径组成。例如：

```text
图片域名      https://img.example.com
公开前缀      /blog/
随机路径      9b7c6d5e4f304162a8b9c0d1e2f34567.jpg

公开链接      https://img.example.com/blog/9b7c6d5e4f304162a8b9c0d1e2f34567.jpg
```

随机文件名由上传 ID 生成，不包含日期或原始文件名。实际使用时直接复制上传结果，不需要手工拼接。域名设置见 [域名与反向代理](../operations/proxy.md)。

随机路径默认使用两层存储目录：上述图片存储为 `9b/7c/9b7c6d5e4f304162a8b9c0d1e2f34567.jpg`，公开链接仍保持平铺。目录层数可选 `0`、`1`、`2`，只影响存储位置。S3 的对象前缀同样只影响桶内位置，不会加入公开链接。插件开发者可进一步区分 `logicalKey` 与 `storageKey`，见 [路径插件协议](../development/plugin-api.md)。

## 修改后对已有图片的影响

- 修改路径、前缀或存储组，用于后续上传；已有文件的路径与副本不会自动改变。
- 修改上传处理规则，不会重新处理已经保存的图片。
- 关闭上传配置，停止接收该入口的新上传，已有图片不会被删除。

全局访问流水线在访问图片时运行，因此调整它也会影响已有图片的访问处理。详见 [三阶段流水线](./pipelines.md)。
