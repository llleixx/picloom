# 理解 Picloom

Picloom 用上传配置组织图片的保存规则。例如，博客图片可以保存到本地并添加水印，截图可以保存到 S3 并保留原始内容。上传时选择相应配置即可。

访问图片时，还可以通过全局访问流水线生成缩略图或转换格式，无需重新上传。

## 配置关系

```text
上传配置
├─ 公开前缀 + 路径插件配置
├─ 存储组
│  └─ 一个或多个存储源
├─ 上传流水线（可选）
└─ 保存后流水线（可选）

全局访问流水线 → 对公开图片访问生效
```

| 对象     | 用途                     | 示例                    |
| -------- | ------------------------ | ----------------------- |
| 插件     | 提供某一种能力           | S3 存储、图片变换       |
| 插件实例 | 绑定配置的插件运行实例   | 连接到你的某个桶        |
| 存储源   | 一个存储插件实例         | 本地磁盘、S3 桶         |
| 存储组   | 选择主存储与冗余存储     | 本地优先，再存一份到 S3 |
| 流水线   | 按顺序执行处理步骤       | 缩放后添加水印          |
| 上传配置 | 组合路径、存储和处理规则 | 博客图片上传入口        |

路径插件的配置在上传配置中编辑；处理插件的配置在流水线步骤中编辑。存储源则单独创建，便于多个上传配置共用。

## 上传成功意味着什么

文件通过上传处理、路径生成和主副本写入后，Picloom 发布文件并返回链接。冗余副本写入、保存后审核或通知作为后台任务执行。

返回链接时，后台任务可能尚未完成。保存后审核仍可能屏蔽或删除图片。

## 文件、原图与副本

一条文件记录对应一个公开路径，可以有一个主副本和多个冗余副本。这里的“原图”指最终保存的图片：若上传流水线修改了内容，保存的是修改后的结果。

访问处理生成的是派生结果，不覆盖这些副本。访问无处理需求时，存储插件可以返回内容流，也可以返回跳转链接。

## 临时空间、缓存与副本

| 名称     | 保存什么                           | 能否当作备份     |
| -------- | ---------------------------------- | ---------------- |
| 临时空间 | 上传、处理中间文件及后台任务源文件 | 不能             |
| 派生缓存 | 可从原图重新生成的访问结果和缩略图 | 不能             |
| 冗余副本 | 同一图片在其他存储源中的内容       | 不能替代完整备份 |

完整恢复还需要数据库、插件配置和加密密钥，见 [数据与备份](../operations/data.md)。
