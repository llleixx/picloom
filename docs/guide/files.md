# 图片管理

## 查看与管理图片

在「图片管理」中查找图片、预览内容、复制链接和删除图片。成员管理自己的图片；管理员可以管理站内图片。

支持按路径或文件 ID 搜索，按状态、格式和日期筛选；管理员还可以按存储源和归属者筛选。列表默认显示可用图片，查找删除中的图片时需切换状态筛选。

点击图片打开详情，查看路径、大小和尺寸，复制原图链接，也可以生成图片处理链接。管理员查看全部图片时，列表与详情的归属位置显示用户名，访客图片显示记录的上传 IP；已登录用户上传时不记录 IP。列表支持批量复制链接和删除图片。

## 标签与集合

分别从侧栏「标签」和「集合」进入管理页面，搜索、新建、编辑名称，或复制 ID 供外部上传工具使用。标签页面也列出尚未关联图片的空标签。集合可填写描述，列表显示可用图片数量，并以最新可用图片自动预览。标签和集合只属于注册用户，管理员可选择自己或指定用户进行管理。

在图片管理中展开「标签、集合与排序」，选择一个或多个标签，并选择「满足全部标签」或「满足任一标签」；也可筛选指定集合、未打标签或未加入集合。其他格式、时间、状态、路径筛选同时生效。点击集合名称可浏览集合内容，仍可调整这些筛选。

打开图片详情，在「标签与集合」中选择或移除项目后保存；选择器支持搜索和就地创建。多选图片后点击「编辑归类」，选择分类并点击「添加所选归类」或「移除所选归类」，保留图片的其他关联。管理员跨归属混选时需先限定同一注册用户。后台处理期间仍可整理图片，但处理步骤可能继续调整最终归类。

上传前选择初始标签和集合，每张图片保留入队时的选择，之后调整仅影响新入队图片。自己的集合中提供「上传到此集合」，默认选中该集合，也可移除或改选；管理员浏览其他用户的集合时不提供此操作，可在对应归属的图片中批量加入集合。访客图片不支持标签和集合，包括管理员整理和插件自动归类。

集合是逻辑分组，不是存储目录；改名、加入或移出集合不会改变图片路径或公开访问。删除标签或集合只解除关联，不删除图片；上传或导入期间已选归类被删除时，图片正常保存并跳过该关联。整图删除完成后清除归类关联，集合只统计可用图片。

## 替换图片并保留链接

1. 在图片管理中打开一张可用图片的详情，点击“替换图片”。成员只能替换自己的图片，管理员可以替换其有权管理的图片。
2. 选择有权限且可用的上传配置和新图片。默认选择原上传配置；原配置已不可用时，需显式选择其他配置。
3. 确认替换，等待新图上传、副本写入与保存后任务成功完成。新图可以使用与原图不同的格式。
4. 完成后用原公开链接检查新内容。图片记录 ID 会更新，保留原图归属、标签和集合，新图上传期间产生的归类会被取代；旧内容随后异步清理。

原图的后台任务未完成时不能替换，已删除副本留下的失败或取消记录不影响替换。新图被审核屏蔽或任务失败时，不能完成切换。切换失败不会删除原图，新上传的图片可能作为独立记录保留；重试前先检查图片列表。

公开链接及其后缀不变，后缀可能与新图实际格式不同。浏览器或 CDN 可能继续显示旧缓存，需等待过期或主动刷新。脚本操作见[替换图片 API](../reference/http-api.md#替换图片)。

## 查看与管理副本

一张图片可以保存在多个存储源中，每份存储称为一个副本。公开链接对应图片，不绑定某个固定副本。

管理员可以在图片详情的「副本」中查看状态，选择删除文件或解除引用。图片详情和列表批量操作均可选择这两种方式。

| 操作         | 影响                                             |
| ------------ | ------------------------------------------------ |
| 处理指定存储源 | 有其他可用副本时仅处理此源，保留公开链接；否则默认处理整张图片及其他源上的失败副本 |
| 处理整张图片 | 停止公开访问，处理所有未终结副本 |

副本数量和存储位置由 [存储组](./storage.md) 决定。

## 删除图片

默认选择「删除文件并解除引用」，后台删除已登记的存储对象。管理员还可选择「仅解除引用，保留文件」：不访问存储，直接结束管理并释放账面容量，仅解除单个副本时保留其记录，原失败任务不可重试。普通成员仍可删除自己的图片。

在图片详情中处理单张图片或单个副本时，没有其他可用副本就会处理整张图片，包括其他源上的失败副本；单项操作不提供保留选项。按存储源批量操作和源清理默认也包含这些图片，可勾选「保留没有其他可用副本的图片」跳过，结果计入「已保留」。处理整张图片后，公开链接立即停止访问；全部副本结束管理且相关任务停止后，自动清除图片及其副本、任务、分类关联等专属记录，释放公开路径，不保留删除历史。人工标记为已删除也按相同规则处理。浏览器或 CDN 已缓存的内容需等待缓存过期。

删除请求接受后显示「删除中」，后台清理失败且任务停止后显示「删除失败」。管理员可在详情中查看错误，修复存储问题后重试失败任务，也可通过同一操作入口选择解除引用。失败表示未确认远端删除成功；缺少已保存的对象定位时，存储插件可能拒绝删除，以免误删同路径的其他文件。正在上传、写入或运行相关任务时，解除引用或副本清理会提示稍后重试。

[NodeImage](https://github.com/llleixx/picloom-extensions/blob/main/plugins/nodeimage/README.zh-CN.md)不支持远端删除，[Telegram](https://github.com/llleixx/picloom-extensions/blob/main/plugins/telegram-storage/README.zh-CN.md)受消息时间和权限限制，可根据结果选择重试或解除引用。

## 导入已有图片

本地存储、S3、[OpenList](https://github.com/llleixx/picloom-extensions/blob/main/plugins/openlist/README.zh-CN.md) 和 [WebDAV](../reference/plugins/webdav.md) 支持导入已有图片，入口位于对应存储源页面。

以迁移 EasyImage 2.0 的图片为例：原图片按 `i/年/月/日/文件名` 保存，如 `i/2026/10/18/photo.jpg`。将 `i` 目录接入 Picloom 后，即可导入，无须重新上传。

1. 在 **配置 → 存储源** 中创建「本地存储」，名称可填 `EasyImage`，根目录指向原图床的 **`i` 目录**。使用 Docker 时，可将该目录挂载到容器的 `/mnt/easyimage`，根目录填 `/mnt/easyimage`；也可将整个 `i` 文件夹移动到 Picloom 的数据目录中。使用仓库提供的 Compose 时，移到宿主机 `./data/app/i`，根目录填 `./i`。具体见 [添加本地存储](./storage.md#添加本地存储)。
2. 保存后打开该存储源的「…」菜单，选择「导入」。**扫描范围留空**，导入整个 `i` 目录。扫描范围用于在存储源内选取子目录：例如只导入 2026 年 10 月的图片，填写 `2026/10`，不包含 `i/`。
3. 公开前缀填写 `/i/`，「公开路径去除层数」保留默认 `0`，保留原图片路径，并选择允许的图片格式。默认上传配置 `Default` 也使用 `/i/`，相同前缀允许共用，无须修改。若希望新上传的图片使用独立前缀，可先在 **配置 → 上传配置** 中将 `Default` 的公开前缀改为 `/uploads/`，已有图片链接不变。
4. 按需选择初始标签和集合，仅用于此次新导入的记录，重复扫描跳过的已有记录不变。点击「开始导入」，完成后在图片管理中检查导入的图片及其公开链接。

默认导入保留相对于存储源根目录的路径，不经过路径插件重新命名。扫描范围只决定导入哪些图片，不会从路径中去掉年月目录：

| 项目                 | 示例                      |
| -------------------- | ------------------------- |
| 原图床中的文件       | `i/2026/10/18/photo.jpg`  |
| 存储源根目录         | 原图床的 `i` 目录         |
| 源中的相对路径       | `2026/10/18/photo.jpg`    |
| 公开前缀             | `/i/`                     |
| Picloom 公开访问路径 | `/i/2026/10/18/photo.jpg` |

要保留完整旧链接，还需让原图床域名指向 Picloom，参见 [域名与反向代理](../operations/proxy.md)。前缀允许嵌套，例如 `/i/` 和 `/i/photos/` 可以共存；只有最终公开路径重复才会冲突，导入会跳过冲突项并计入冲突数量，不覆盖已有图片。

若图片采用分片目录存储，例如 `ab/cd/abcdef.jpg`，可将「公开路径去除层数」设为 `2`，得到 `/i/abcdef.jpg`。此项从存储源内的完整路径开头计算，与扫描范围无关；只改变公开路径，不移动文件，也不修改存储定位信息。目录不足的条目计为失败，去除后公开路径重复的条目计为冲突。

重复导入同一存储对象会跳过，不新增记录；修改去除层数或公开前缀后重新扫描，也不会重命名已经导入的记录。

导入只建立引用，不复制文件，不执行上传流水线，也不自动补充副本。

扫描期间请保持页面打开。点击「扫描完本页后停止」会在当前页结束后停止，已导入的图片记录保留。

导入后在 Picloom 删除图片，也会删除存储源中的原文件。若这些文件仍供其他服务使用，请先确认可以交由 Picloom 管理。
