# 文件、副本与导入

## 管理文件

图片管理页用于查询、预览、复制链接和删除文件。成员管理自己的文件；站点管理员可以管理站内文件。

文件被屏蔽或进入删除流程后，Picloom 不再正常提供公开访问。已被浏览器或 CDN 缓存的内容可能继续保留到缓存过期。

## 删除文件与副本

删除文件先改变数据库状态，再由后台任务删除副本。远端不可用时可能出现删除失败或结果不确定，可在操作详情中查看结果。

删除单个副本与删除整个文件不同：前者用于清理某个存储源中的副本，正常文件需要保留可用副本。当前人工重试入口针对失败的删除任务。

操作结果“不确定”表示暂时无法确认远端是否已经完成写入或删除。可结合任务错误与存储端状态排查，不应直接当作文件不存在。

## 导入已有文件

导入用于接管已经在存储中的图片，例如让桶内的 `album/photo.jpg` 通过 Picloom 链接访问。它不需要先把图片下载到电脑再上传。

1. 在 **配置 → 存储源** 找到支持枚举文件的源，打开“导入”。没有此入口时，说明该源不支持导入。
2. 设置扫描范围。例如只导入 `album/` 下的图片，可填写 `album`；留空扫描整个存储源。
3. 设置未与已有配置冲突的公开前缀，例如 `/archive/`，并勾选允许格式。页面会显示路径示例。
4. 点击“开始导入”，等待扫描完成，查看已导入、跳过、冲突和失败数量。
5. 在图片管理页找到导入项，打开其公开链接，确认能够访问。

导入保留源中的相对路径。例如 `album/photo.jpg` 配合 `/archive/` 后形成 `/archive/album/photo.jpg`，不会通过路径插件重新命名。

点击“扫描完本页后停止”会在当前页结束后停止，已经导入的记录保留。导入过程由页面逐页发起，应保持页面打开直到完成或停止。

导入只建立引用，不复制文件，也不运行上传流水线或自动补冗余副本；部分图片元数据会在后续读取时补齐。

::: warning 删除会影响源文件
导入后在 Picloom 删除图片，也会删除原存储中的对象。若该目录或桶仍供其他服务使用，应先确认这些文件可以交由 Picloom 管理。
:::
