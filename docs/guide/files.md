# 图片管理

## 查看与管理图片

在「图片管理」中查找图片、预览内容、复制链接和删除图片。成员管理自己的图片；管理员可以管理站内图片。

支持按路径或文件 ID 搜索，按状态、格式和日期筛选；管理员还可以按存储源和归属者筛选。列表默认显示可用图片，查找删除中的图片时需切换状态筛选。

点击图片打开详情，查看路径、大小和尺寸，复制原图链接，也可以生成图片处理链接。管理员查看全部图片时，列表与详情的归属位置显示用户名，访客图片显示记录的上传 IP；已登录用户上传时不记录 IP。列表支持批量复制链接和删除图片。

## 标签与集合

在侧栏「标签」或「集合」创建分组。在图片管理展开「标签、集合与排序」筛选图片。点击集合名称可直接查看其中的图片。

| 操作 | 步骤 |
| --- | --- |
| 整理单张图片 | 打开详情，在「标签与集合」中选择或移除项目后保存 |
| 批量整理 | 多选同一用户的图片，点击「编辑归类」，选择添加或移除 |
| 上传时归类 | 上传前选择标签和集合，或在自己的集合中点击「上传到此集合」 |

归类只适用于注册用户的图片。删除标签或集合只解除关联，图片和公开链接仍可用。

## 替换图片并保留链接

1. 在图片管理中打开一张可用图片的详情，点击“替换图片”。成员只能替换自己的图片，管理员可以替换其有权管理的图片。
2. 选择有权限且可用的上传配置和新图片。默认选择原上传配置；原配置已不可用时，需显式选择其他配置。
3. 确认替换，等待新图上传、副本写入与保存后任务成功完成。新图可以使用与原图不同的格式。
4. 完成后用原公开链接检查新内容。图片记录 ID 会更新，保留原图归属、标签和集合，新图上传期间产生的归类会被取代；旧内容随后异步清理。

替换前先确认原图的后台任务已完成。新图被屏蔽或任务失败时，无法完成切换。切换失败不会删除原图，新上传的图片可能作为独立记录保留；重试前先检查图片列表。

公开链接及其后缀不变，后缀可能与新图实际格式不同。浏览器或 CDN 可能继续显示旧缓存，需等待过期或主动刷新。脚本操作见[替换图片 API](../reference/http-api.md#替换图片)。

## 查看与管理副本

一张图片可以保存在多个存储源中，每份存储称为一个副本。公开链接对应图片，不绑定某个固定副本。

管理员在图片详情的「副本」中查看每份副本的状态。副本数量和存储位置由[存储组](./storage.md#创建存储组)决定；需要清理某个副本时，按下节选择操作范围。

## 删除图片

删除整张图片可从列表批量操作，也可在图片详情中操作。管理员还可在详情的「副本」中处理指定存储源的副本。

| 操作方式 | 结果 |
| --- | --- |
| 删除文件并解除引用（默认） | 后台删除已登记的存储文件 |
| 仅解除引用，保留文件（管理员） | 结束管理并释放账面容量，存储中的文件保留 |

处理指定副本时，有其他可用副本就只处理所选副本，公开链接仍可用。没有其他可用副本时，默认处理整张图片。按存储源批量操作或清理存储源时，可勾选「保留没有其他可用副本的图片」跳过这类图片。

处理整张图片后，公开链接停止访问，浏览器或 CDN 已有缓存可能继续显示。清理完成后删除图片记录，释放公开路径。

若显示「删除失败」，管理员可在图片详情查看错误，修复后重试，或选择仅解除引用。遇到正在上传、写入或运行相关任务的图片，按界面提示稍后重试。

[NodeImage](https://github.com/llleixx/picloom-extensions/blob/main/plugins/nodeimage/README.zh-CN.md)不支持远端删除，[Telegram](https://github.com/llleixx/picloom-extensions/blob/main/plugins/telegram-storage/README.zh-CN.md)受消息时间和权限限制，可根据结果选择重试或解除引用。

## 导入已有图片

本地存储、S3、[OpenList](https://github.com/llleixx/picloom-extensions/blob/main/plugins/openlist/README.zh-CN.md) 和 [WebDAV](../reference/plugins/webdav.md) 支持导入已有图片，入口位于对应存储源页面。

### 保留 EasyImage 的旧路径

例如将 `i/2026/10/18/photo.jpg` 导入为 `/i/2026/10/18/photo.jpg`：

1. 在 **配置 → 存储源** 创建本地存储，根目录指向 EasyImage 的 `i` 目录。Docker 部署可把该目录挂载到容器的 `/mnt/easyimage`，根目录填 `/mnt/easyimage`。见[添加本地存储](./storage.md#添加本地存储)。
2. 打开存储源的 **… → 导入**，按下表填写。

| 设置 | 值 |
| --- | --- |
| 扫描范围 | 留空扫描整个 `i` 目录，或填 `2026/10` 等相对路径 |
| 公开前缀 | `/i/` |
| 公开路径去除层数 | `0`，保留原有子目录 |
| 图片格式 | 选择要导入的格式 |

3. 点击「开始导入」，保持页面打开。完成后在图片管理打开一张导入的图片，验证链接。要保留完整旧链接，还需让[原域名指向 Picloom](../operations/proxy.md)。

### 导入结果

- 导入直接登记存储中的原文件。它会跳过已登记的对象及公开路径冲突的图片。
- 「公开路径去除层数」从存储源内的完整路径起算。例如对 `ab/cd/abcdef.jpg` 去除两层，公开路径为 `/i/abcdef.jpg`。
- 若原文件仍供其他服务使用，在 Picloom 清理时选「仅解除引用，保留文件」。
