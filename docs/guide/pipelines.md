# 三阶段流水线

打开 **配置 → 流水线**，按阶段配置步骤。步骤顺序就是执行顺序，每个步骤有独立的插件配置。

| 阶段   | 什么时候执行         | 主要用途                 | 配置位置             |
| ------ | -------------------- | ------------------------ | -------------------- |
| 上传   | 主副本写入前         | 缩放、水印，改变保存内容 | 创建后由上传配置选择 |
| 访问   | 读取公开图片时       | 按参数生成不同尺寸或格式 | 全局访问流水线       |
| 保存后 | 文件发布后的后台任务 | 审核、通知               | 创建后由上传配置选择 |

## 创建并使用流水线

1. 打开 **配置 → 流水线**，创建上传或保存后阶段的流水线，填写名称。
2. 添加处理插件，填写该步骤的配置。只有支持当前阶段的插件可用于该阶段。
3. 调整步骤顺序并保存。例如先缩放再加水印，水印按缩放后的图片尺寸生成。
4. 编辑上传配置，选择刚创建的流水线并保存。

上传和保存后流水线可以被多个上传配置共用，编辑共用流水线会影响这些配置。全局访问流水线直接在流水线页面编辑，保存后作用于公开图片访问，无需绑定到某个上传配置。

## 固定配置与请求参数

固定配置由管理员保存，请求参数由上传者或访问者提供。以 **Sharp 图片处理** 为例：

| 需求 | 配置方法 |
| --- | --- |
| 新上传图片统一缩小到宽 1600 | 在上传步骤配置宽度 `1600`，不开放 `w` 请求参数 |
| 上传者可自行指定宽度 | 在上传步骤启用 `w`，通过上传 API 的 `params` 传值 |
| 用链接生成不同尺寸 | 在访问步骤启用 `w`，访问时使用 `?w=320` |

同一参数在上传和访问步骤中分别启用。未启用的参数不会传入步骤；启用后，类型或数值不合法会报错。访问参数的完整说明见 [图片参数](../reference/image-params.md)。

## 不适用时跳过还是中止

例如，Sharp 图片处理支持静态 JPEG、PNG、WebP，遇到 GIF 或 SVG 时会判为不适用：

- **跳过**：继续后面的步骤，这张图片可能保持原样。
- **中止**：本次上传或访问失败，避免返回不符合处理要求的图片。

允许保留原样时可选择跳过；要求每张保存图片都必须完成该处理时应选择中止。该选项只处理“不适用”的情况，网络错误、无效配置等执行异常仍会失败。

## 审核与通知

保存后步骤可返回放行、屏蔽或删除。屏蔽和删除会停止后续步骤；审核放在通知之前，可以避免继续通知已经判定不通过的图片。

保存后处理是异步的，不能用来保证图片在首次公开之前已完成审核。访问缓存与客户端缓存的区别见 [容量与并发](../operations/resources.md)。
